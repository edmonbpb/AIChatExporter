## ۰. دو قانون که کل این پلان روی آنها می‌چرخد

۱) **شاهد، نه حدس.** هیچ باگی «پیدا شد» حساب نمی‌شود مگر یک artifact داشته باشد: خروجی `adb -s … shell …`، فایل `docs/reports/raw/*.xml`، XML تست، یا عددِ اندازه‌گیری‌شده. هیچ رفعی «انجام شد» حساب نمی‌شود مگر آن artifact بعد از تغییر، دوباره تولید شده باشد.
۲) **قرمزِ عمدی.** هر تستی که اضافه می‌کنید باید ثابت کند می‌تواند قرمز شود: رفتار موردنظر را یک‌جا خراب کنید، اجرا کنید، قرمز بودن را ببینید، بعد برگردانید. اگر تست با کدِ خراب‌شده سبز ماند، آن تست جایش درست نیست (این دقیقاً یک بار در این پروژه اتفاق افتاد: حذفِ نگهبانِ چرخه، تست سبز ماند).

## ۱. قدم صفر — قابل‌تشخیص‌کردن (بدون این، عیب‌یابی یعنی حدس‌زدن) — **انجام شد، ۲۰۲۶-۱۰-۰۸**

وضعیت پیش از کار (اندازه‌گیری با `grep` روی `app/src/main/java/com/example/`): ۳۳ نقطۀ `catch`/`return null` در مسیر استخراج لینک، که ۶ تای آن `catch (_: Exception) {}` کاملاً خالی بود، و `tryFetchJinaReader` کد HTTP را دور می‌ریخت. نمونهٔ زنده: لینک Claude روی گوشی شکست می‌خورد و هیچ‌کس نمی‌دانست کدام لایه، با چه کدی و با چه حجمی (سند: `docs/reports/claude-share-round-2026-10-08.md` بند ۵).

کاری که انجام شد (همه در `SharedLinkExtractor.kt`):

- `private data class FetchOutcome(body, httpCode, bytes, error)` و بازگشت همین شیء از هر سه `tryFetch*`؛ هیچ `catch` بی‌صدایی نمانده (نامِ استثنا در `error` ثبت می‌شود).
- یک خطِ پیشرفت برای هر لایۀ شبکه از راه همان `onProgress` که از `extractFromUrl` می‌گذرد: «لایه ۲: HTTP ۴۰۱، ۰ بایت، پاسخ غیرموفق موتور خواندن».
- جمع همان خطوط و چسباندنشان به پیام `Result.failure`؛ رابط (`MainViewModel.kt`) پیام را عیناً روی کارت نشان می‌دهد. دو پیامِ متفاوت: اگر هیچ بایتی نیامد ← «اتصال برقرار نشد»؛ اگر بایت آمد و گفتگو نبود ← ادعای رندر/بی‌محتوا.
- «پاک‌ساز همه را حذف کرد» از «صفحۀ بدون گفتگو» جدا شد (خطِ تشخیصی مخصوص خودش).

معیار پذیرش و نتیجه‌ای که گرفتیم: با لینک واقعی Claude روی گوشی، کارت خطا باید بگوید کدام لایه چه کدی گرفت — **گفت**. شاهد `docs/reports/raw/ui-claude-04-clean.xml`: سه خطِ `لایه ۱: HTTP ۱۰۳، ۰ بایت` / `لایه ۲: HTTP ۴۰۱، ۰ بایت` / `لایه ۳: HTTP ۵۲۲، ۰ بایت`. یک اجرا، سه علت. بدون همین، این پرونده «احتمالاً فیلترشکن» می‌ماند.

## ۲. حلقۀ تکرارشوندی (هر باگ، هر بار)

```
بازتولید → ایزوله → ثبتِ شاهد → اصلاح → قرمزِ عمدی → تأیید روی دستگاه → به‌روزرسانی سند
```

- **بازتولید:** ورودی ثابت. متن‌های آماده در `docs/reports/raw/` (`mid-chat.txt` ۶۲ کیلوبایت، `long-chat2.txt`، `resume-marker.txt` با نشانگر `ZORK7731`). لینک‌های واقعی: یک share چت‌جی‌پی‌تی (کار می‌کند)، یک share Claude (روی `emulator-5554` بی‌کلید کار می‌کند — ۲۰۲۶-۱۰-۰۹؛ از egress گوشیِ ۲۰۲۶-۱۰-۰۸ نه).
- **ایزوله:** کوچک‌ترین ورودی که باگ را می‌دهد؛ برای پارسرها، یک رشتهٔ inline داخل تست (نه fixture بزرگ).
- **ثبت شاهد:** `MSYS_NO_PATHCONV=1`، همه با `-s`، helperِ ساختارِ صفحه `tools/uidump.sh`، و لاگ کرش *دور* اجرا:
  ```bash
  S=R58X30GS9QJ; PKG=com.aistudio.aichatexporter.kxrtva
  # از ۲۰۲۶-۱۰-۰۹ دستگاهِ پیش‌فرضِ تست `emulator-5554` (شبیه‌ساز LDPlayer) است؛ گوشی فقط با درخواستِ صریحِ کاربر
  adb -s $S shell am force-stop $PKG
  adb -s $S logcat -c -b crash
  adb -s $S shell sh /sdcard/share_url.sh          # یا am start با اکسترا
  sleep 25; sh tools/uidump.sh $S docs/reports/raw/<name>.xml
  adb -s $S logcat -d -b crash -t 400 -v brief | wc -l   # باید ۰ باشد
  ```
- **دروازهٔ محلی:**
  ```bash
  ./gradlew :app:assembleDebug :app:testDebugUnitTest --offline --console=plain
  PYTHONIOENCODING=utf-8 python /tmp/fa_check.py <فایل‌های دست‌خورده> --min-persian 0   # ۰ یافته
  ```
  **تصحیح ۲۰۲۶-۱۰-۱۱:** آن اسکریپت موقت دیگر وجود ندارد؛ دروازۀ همیشگیِ همان بررسی `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/verify.ps1 -Stage 3` است (خروجیِ پذیرفتنی: `findings=0`). ارجاعِ مردهٔ دومِ همین بند `tools/uidump.sh` است: اسکریپت هست، ولی `uiautomator` روی این نسخۀ شبیه‌ساز بعد از کشتنِ یک دامپ تا پایانِ عمرش می‌میرد (ردیف `B-۲۶`)، پس شاهدِ صفحۀ بیرونی با `screencap` + مختصاتِ دامپ‌هایِ ذخیره‌شده گرفته می‌شود.
  بعد از هر تغییر، `ls -l --time-style=+%H:%M:%S app/build/outputs/apk/debug/app-debug.apk` را با ساعت خودِ گوشی (`adb -s $S shell date`) مقایسه کنید: اگر APK قدیمی‌تر از آخرین ویرایش است، چیزی که نصب کرده‌اید آن کد نیست.

## ۳. جهات باگ‌یابی (به ترتیب اولویت، با چک‌قابل‌اجرای هر جهت)

### ۳.۱ استخراج لینک (بالاترین ارزش، بیشترین باگ‌خیز بودن)
- هر پنج لایه را جدا بسنجید: `curl` روی میزبان با همان هدرها، بعد روی دستگاه از راه اپ. کدهای ۴۰۱/۴۲۹/۴۰۳ را یادداشت کنید.
- دروازۀ `usable`: آیا یک پوستهٔ بی‌محتوا هنوز می‌تواند از لایۀ ۵ (`createFallbackSession`) به‌عنوان «گفتگو» رد شود؟ (این تابع عمداً یک پرسش + یک پاسخ می‌سازد → دروازۀ فعلی همیشه درست برمی‌گردد. چک: تست JVM با متنِ ۴۸۱ کاراکتریِ همین صفحۀ Claude؛ انتظار: رد.)
- شمارش نوبت‌های ردشده (بند ۸.۱ نقشهٔ راه): صفحۀ «smart content»/canvas نباید «موفق» به‌نظر برسد.
- رمزگشای تک‌جریانی: صفحۀ چندتکه، گره‌های با `parent/children` واقعی، و `MAX_SLOTS` (سقف فعلی ۱۲۰٬۰۰۰).

### ۳.۲ احراز هویت و حساب
- ورود/خروج/«لغو شد»/«پیکربندی نشده» — هر چهار حالت روی دستگاه.
- `signOut()` باید پیش‌نویس را پاک کند و تم/اندازۀ فونت را نگه دارد (این پاک‌شدنِ پیش‌نویس روی دستگاه سنجیده نشده؛ بقیهٔ مسیرها سنجیده شده‌اند).
- چند حساب گوگل روی دستگاه: حساب دوم را انتخاب کنید، ببینید پروفایل عوض می‌شود یا نه.
- اعتبارسنجی توکن: `exp/aud/iss/nonce/email` (۷ تست JVM موجود؛ با تغییر کد، قرمزِ عمدی را امتحان کنید).

### ۳.۳ ماندگاری و بازیابی
- بازیابی مکالمهٔ باز: متن → کشتن پروسه → شروع سرد (سناریوهای تأییدشده: ۴ پیامی، ۹۲ پیامی، و «نسخۀ دیتابیس بر پیش‌نویس مقدم است»).
- همزمانی نوشتن پیش‌نویس: دو ویرایش پشت‌هم روی یک `resume_draft.json.tmp` (نگهبان ندارد؛ با `am start` سریع یا اسکریپت، ببینید فایل نیمه‌کاره می‌ماند یا `load` سالم است).
- Room: مهاجرت‌ها، کلید خارجی (`SQLiteConstraintException` که قبلاً روی گوشی رخ داد)، و `allowBackup="true"` (پیش‌نویس + دیتابیس + کلید API به بکاپ ابری می‌روند — بند ۱۱ نقشهٔ راه؛ حریم خصوصی).

### ۳.۴ صدور سند
- هفت فرمت × (فارسی خالص / دوزبانه / کد بلند / ۶۲ کیلوبایت متن). برای PDF: `pdftotext` و جستجوی نشانگرِ انتهای متن (تکنیکِ ثابت‌شده برای «بریدن محتوا»).
- مسیر عمومی: `md5sum` فایل خصوصی و رونوشتِ `/sdcard/Download` روی *دستگاه* باید یکی باشد؛ `is_pending` باید ۰ باشد؛ و در pathِ خطا (جای دیسک پر) نباید صفرتعبایتی در Download بماند.
- `styles.xml` واقعی Word (بند ۴ نقشهٔ راه) هنوز انجام نشده؛ مرده‌کدِ `generatePresentation`/`generateWordDocx` (بند ۸) **حذف شد** (۲۰۲۶-۱۰-۱۰، ۱۶۰ خط از `DocumentExporter.kt`؛ هر دو `private` و صفر فراخوان، هیچ فرمتی از رابط کم نشد).

### ۳.۵ رابط و تعامل
- تداخل نوار پایین با دکمه‌های گوشی (بازگشتِ رگرسیون؛ `WindowInsets.navigationBars`).
- ناوبریِ مرحله‌ای: دکمهٔ بازگشت از کتابخانه/تنظیمات نباید محیط کار را بی‌اجازه باز کند (بند ۱۰).
- کارکرد لمس‌محورِ چیزهایی که adb نمی‌تواند ثابت کند: کیبورد فارسی، submit در Compose، و کشیدنِ تاریخچۀ بلند (بند ۶ نقشهٔ راه: دکمهٔ بوکمارک روی کارت کتابخانه).
- اعداد فارسی: هر شمارشی که در رابط می‌بینید باید با `BidiEngine.toPersianDigits` رندر شود (یک `grep` ساده: `messages.size` بدون تبدیل).

### ۳.۶ کارایی و حافظه
- زمانِ شروع سرد با پیش‌نویس ۷۷ کیلوبایتی؛ زمانِ استخراج صفحۀ ۸۶۵ کیلوبایتی (باید روی `Dispatchers.IO` باشد و UI فریز نشود: `dumpsys gfxinfo $PKG` یا «Skipped frames» در logcat).
- پیک حافظۀ بازکردن آرایۀ تخت؛ PPTX با اسلایدهای زیاد؛ PDF ۱۰+ صفحه.

### ۳.۷ ساخت/توزیع
- `assembleRelease` با keystore (بند ۱۳) و اندازه/APK و مجوزها (`aapt dump badging`).
- `:app:lint` و `:app:kspDebugKotlin` warningها (مثلاً `fallbackToDestructiveMigration` deprecated).

### آزمایش بعدی (به ترتیب ارزش)

۱. **۱xx را نهایی نشمار.** `HTTP 103` روی `claude.ai` همان چیزی است که لایه ۱ را می‌کُشد. دو حدسِ قابل آزمون: (الف) کلاینت را به `Protocol.HTTP_1_1` محدود کن و ببین `200` می‌آید یا نه؛ (ب) اگر `200` آمد ولی بدنه همان پوسته بود، `looksLikeConversation` باید خودش را ثابت کند و آنگاه پروندۀ Claude فقط به لایۀ رندر می‌رسد. هر دو در **یک اجرا** از روی کارتِ تشخیصیِ جدید خوانده می‌شوند.
۲. **تصمیم برای لایۀ رندر — اخذ شد (۲۰۲۶-۱۰-۰۹): کاربر کلید ندارد.** `r.jina.ai` از میزبان بدون کلید کار می‌کند و از egress گوشی `401` می‌دهد. فیلد «کلید موتور خواندن» ساخته شد و **اختیاری** باقی می‌ماند؛ چون کلیدی در دسترس نیست، مسیرِ پیش‌فرضِ لینک Claude همان **کپیِ دستی** است و پیامِ خطا هم از همین لحظه همین را اول می‌گوید، نه «برو کلید بگذار». (این تصمیم جای ادعای «کلید لازم است» را گرفت؛ همان ادعا در همان روز با بند ۵ِ همین فهرست نقض شد.) (باگِ خام نبود؛ تصمیمِ محصول بود.)
۳. **یک رابطۀ واقعیِ تک‌جانبه.** رمزگشای چت‌جی‌پی‌تی نوبت‌های `multimodal_text` را دور می‌ریزد؛ یک لینکِ دارای تصویر پیدا شود تا دیده شود `takeIf { usable(it) }` در همان لایه درست عمل می‌کند یا هنوز چیزی می‌شکند.
۴. **صفحه‌های بی‌نشانه.** حالا چنین صفحه‌ای عمداً رد می‌شود. اگر نمونه‌ واقعیِ بی‌نشانۀ کاربر پیش آمد، آستانه بازبینی شود — با افزودن نشانه‌های بیشتر، نه با شل کردن دروازه.
۵. **تأییدِ بی‌کلید روی شبیه‌ساز (۲۰۲۶-۱۰-۰۹، اندازه‌گیری‌شده).** همان لینک Claude روی `emulator-5554` (LDPlayer، اندروید ۱۴ / API ۳۴، `x86_64`، `1080x1920 @480dpi`) بدون هیچ کلیدی وارد شد: «پرسش‌های کاربر (۳) / پاسخ‌های هوش مصنوعی (۲)»، کلمات ۷۱۴، مدل `Claude 3.5 Sonnet`، و بافر کرش صفر خط. `run-as` فایل `files/resume_draft.json` (۹٬۲۲۵ بایت) را بیرون داد و خوانده شد: ۵ نوبت، با دو پاسخِ ۲٬۵۲۵ و ۳٬۰۶۷ کاراکترِ متنِ گفتگو — نه عناصرِ پوسته؛ و یکی از همان سه «پرسش» حبابِ خالیِ فقط-آیکون بود (ردیف B-۰۸). پس لایۀ ۲ که روی میزبان `8٬626` بایت Markdown می‌داد، روی این دستگاه هم گفتگوی واقعی ساخت؛ ادعای «کلید لازم است» تنها به egressِ گوشی برمی‌گشت، نه به خودِ اپ. شاخۀ «۴۰۱ بی‌کلید» تا امروز فقط از همان مسیرِ اینترنتِ گوشی (SM-A155F) دیده شده است.
